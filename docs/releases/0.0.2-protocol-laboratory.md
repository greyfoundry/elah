# 0.0.2 - Protocol Laboratory

Protocol Laboratory proves that an Elah Rust controller and a Java worker can share a versioned gRPC contract and survive repeated process replacement under machine-checked lifecycle rules.

## Demonstrated scope

- Rust, Java, and JavaScript/TypeScript bindings generated from one Buf-validated contract.
- A plaintext Rust `elahd` listener that refuses non-loopback addresses.
- An in-memory worker registry with stable worker IDs, per-process session IDs, monotonic generations, idempotent duplicate heartbeats, and permanent retirement of replaced sessions.
- A Java dummy worker that registers and emits sequenced heartbeats across the real gRPC transport.
- An ordered Node.js evidence ledger that cannot pass with missing or reordered registration, heartbeat, forced-death, reconnect, or retired-session-rejection stages.
- A GitHub-hosted release gate that performs an initial worker lifecycle plus 25 reconnects: 26 forced process deaths and final generation 26.

The release-gate report is uploaded from the `Protocol Laboratory (25 reconnects)` CI job as `protocol-laboratory-report`.

## Explicit non-goals

This release has no Minecraft server, Folia or Velocity integration, Mineflayer client, cell ownership, placement, storage, persistence, TLS, authentication, automatic failover, player transfer, or gameplay behavior. The registry is intentionally lost when `elahd` exits. Plaintext transport is for one-machine laboratory use only.
